🛡️ Bản Tin Kiểm Tra Quyền Hạn (Authority S002 / S003) Operator Card Validation
Chi tiết quy trình giải mã chuỗi quét thẻ từ máy xưởng và cấp phép vận hành dựa trên Oracle ADM_USER_INFO.
QUY TRÌNH BẢN TIN THỰC TẾ

1. Bản tin EQP gửi lên (S002):

REFLOW12AS002AUTHORITY     ;OP^VM3193023^VM3193023@;AUTHORITY
  • Equipment: REFLOW12A
  • State: S002 | Div: AUTHORITY
  • Loại thẻ: OP^ (Operator) hoặc ME^ (Maintenance Engineer)
  • Mã thẻ: VM3193023

2. MC Server phản hồi (S003):

XREFL012AS003AUTHORITY     ;OK^[ELIS001S] Validation successfully completed.;AUTHORITY
  • Tên máy chuẩn DB: XREFL012A (Tự động ánh xạ từ MIGHTY.GATEWAY_DEVICES)
  • Kết quả: OK^ (Thành công) hoặc NG^ (Không hợp lệ)
  • Mã thông báo: [ELIS001S] (Thành công), [ELIS002F] (Thẻ không tồn tại)

⚙️ Kiến Trúc Chuyên Sâu Backend (NestJS) Core Engine
Cấu trúc module, dịch vụ quản lý Socket TCP, xử lý nhị phân và tối ưu hóa hàng đợi.
CẤU TRÚC PHÂN TẦNG DỊCH VỤ (SERVICE LAYERS)
  • TcpClientManagerService: Quản lý vòng đời kết nối TCP Sockets tới 1.000 máy. Áp dụng setNoDelay(true), setKeepAlive, bộ đệm phân phối lệch pha và Smart Heartbeat.
  • CommunicationService: Xử lý nhận frame nhị phân, giải mã CRC-16, điều hướng tới CommandDispatcher và phát luồng RxJS transactionStream$.
  • AuthorityService: Bóc tách bản tin S002, tra cứu Oracle ADM_USER_INFO, ánh xạ tên máy qua MIGHTY.GATEWAY_DEVICES và sinh gói tin S003.
  • TransactionRepository: Quản lý bộ đệm 5.000 bản ghi RAM và hàng đợi ghi nền định kỳ 500ms vào bảng MC_TRANSACTION_LOG.
CẤU HÌNH CỔNG & PROTOCOL
// Cấu hình giao thức nhị phân công nghiệp
STX: 0x02 (Start of Text)
Length: 2 Bytes (Big Endian)
Device ID: 1 Byte
Server No: 1 Byte
Command Code: 4 Bytes ASCII (VD: 'M001', 'B101')
Sub Code: 1 Byte
Payload: N Bytes Binary
CRC-16: 2 Bytes (Poly 0xA001)
ETX: 0x03 (End of Text)
🗄️ ORACLE LAZY-LOADING CONNECTION POOL & HEARTBEAT 45s Enterprise Resilience

Khởi Tạo Pool Theo Nhu Cầu (On-Demand):

  • Hỗ trợ định tuyến đa TNS: ITMVMES (Chính), ITMMES (Dự phòng), ITMSEMIMES, ITMDEV.
  • Không tạo pool dư thừa lúc khởi động, chỉ kết nối khi phát sinh giao dịch đến TNS đó.
  • Tự động kích hoạt Thick mode tương thích verifier 0x939 cho Oracle 11g/12c.

Tự Động Tái Kết Nối & Xác Thực Nhóm:

  • Heartbeat 45s: Gửi lệnh SELECT 1 FROM DUAL ngầm giữ kết nối xuyên suốt Firewall.
  • Auto-Reconnect: Khi gặp lỗi đứt kết nối (ORA-03113/ORA-03114), tự tạo lại pool và thử lại giao dịch.
  • Đối chiếu nhóm: Bắt buộc khớp EIF_OPER_GROUP (Công đoạn) và EIF_EQP_GROUP (Thiết bị) trên bảng ADM_GROUP_CATEGORY_DATA.

🔧 Sổ Tay Xử Lý Sự Cố (Troubleshooting Matrix) Lỗi & Khắc Phục
Hướng dẫn chẩn đoán và khắc phục nhanh các sự cố thường gặp trong nhà máy.
1. Máy sản xuất báo OFFLINE hoặc ECONNREFUSED
Nguyên nhân: Thiết bị ngoài xưởng chưa bật nguồn, chưa bật cổng TCP Server (5010), hoặc bị chặn bởi Firewall nội bộ.
Cách xử lý:
  1. Kiểm tra ping tới IP máy từ MC Server: ping 192.168.35.xxx
  2. Kiểm tra cổng thiết bị: Test-NetConnection -ComputerName 192.168.35.xxx -Port 5010
  3. Trên Web Dashboard, bấm nút Kết Nối Lại để kích hoạt socket mới.
2. Quẹt thẻ quầy Reflow báo NG: [ELIS002F] Operator not found
Nguyên nhân: Thẻ nhân viên chưa được đăng ký trong bảng Oracle ADM_USER_INFO của nhà máy ITMVIET, hoặc công nhân quét thẻ đang gắn cờ bảo trì (EXPAND_FLAG4 = 'Y') trong khi máy yêu cầu OP^.
Cách xử lý: Liên hệ phòng IT/MES kiểm tra tài khoản trên bảng ADM_USER_INFO với điều kiện EXPAND_FLAG4 = 'N'.
3. Hệ thống chuyển sang FALLBACK_CACHE (Mất kết nối Oracle)
Nguyên nhân: Đường truyền tới máy chủ Oracle ITMVMES (192.168.35.202:1521) bị gián đoạn. MC Server đã tự động kích hoạt chế độ In-Memory Cache an toàn để thiết bị không bị dừng đột ngột.
Cách xử lý: Kiểm tra dịch vụ Oracle Listener trên server 192.168.35.202. MC Server đã trang bị sẵn cơ chế Heartbeat 45s và Auto-reconnect, khi mạng khôi phục sẽ tự động tạo lại pool và tái kết nối.
4. Lỗi: Mã công đoạn và thiết bị không cùng nhóm phân loại nghiệp vụ
Nguyên nhân: Nhóm của công đoạn (EIF_OPER_GROUP) không trùng khớp với nhóm của thiết bị (EIF_EQP_GROUP) trên bảng Oracle ADM_GROUP_CATEGORY_DATA.
Cách xử lý: Kiểm tra bảng ADM_GROUP_CATEGORY_DATA với GROUP_TARGET='OPERATION' (INDEX='22') và GROUP_TARGET='EQUIPMENT' (INDEX='13') để đảm bảo GROUP_VALUE trùng nhau hoặc chọn đúng mã máy thuộc chuyền sản xuất.
5. Màn hình giao diện xuất hiện khung cảnh báo đỏ "Không thể tải phân hệ chức năng"
Nguyên nhân: Lỗi biệt lập trong component con được cách ly an toàn bởi tầng bảo vệ ErrorBoundary để không làm sập toàn bộ ứng dụng.
Cách xử lý: Nhấp vào nút Thử Lại Giao Diện để phục hồi tức thời hoặc Tải Lại Trang để làm mới bộ nhớ cache trình duyệt.
6. Lỗi Oracle Thin Mode (NJS-116 / ORA-28040 verifier 0x939)
Nguyên nhân: Phiên bản Oracle Database 11g/12c yêu cầu giao thức xác thực mật khẩu kiểu cũ mà node-oracledb Thin mode không hỗ trợ.
Cách xử lý: Đảm bảo biến môi trường ORACLE_CLIENT_PATH trỏ đúng thư mục Oracle Instant Client 64-bit (ví dụ: C:\app\client\IT2-LAP-007\product\12.2.0\client_2\bin).
